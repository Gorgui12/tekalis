5. Architecture
Primary App: apps/tekalis-next (Next.js 15 + App Router)
- Routing: Next.js App Router (file-based, app/ directory)
- Rendering: Hybrid SSR + client components (Server Components fetch data, pass to Client Components)
- State Management: Redux Toolkit + Redux Persist (persisted slices: auth, cart, wishlist)
- API Layer: Dual approach:
- lib/serverFetch.js -- Server Components (native fetch with Next.js revalidation)
- lib/api.jsx -- Client Components (Axios instance with interceptors, goes through /api/v1 proxy)
- Styling: Tailwind CSS v4 (via @tailwindcss/postcss), dark mode via class strategy
- Icons: react-icons (FontAwesome subset via react-icons/fa)
- SEO: Excellent -- dynamic sitemap.js, robots.js, OpenGraph, Twitter cards, Schema.org JSON-LD (LocalBusiness, WebSite, CollectionPage), Google verification, canonical URLs, metadata per page
- Deployment: Vercel (configured in vercel.json)
Legacy App: apps/client (Vite + React Router SPA)
- Routing: React Router v7 (SPA)
- State Management: Redux Toolkit + Redux Persist
- Styling: Tailwind CSS v3
- Build: Vite with advanced chunking strategy, console removal in production
- SEO: react-helmet-async for meta tags, react-snap for pre-rendering
- Payment: Stripe integration (@stripe/react-stripe-js)
- Analytics: Google Analytics 4 (react-ga4)
Admin App: apps/admin (Vite + React Router SPA)
- Routing: React Router v7
- State Management: Redux Toolkit + Redux Persist
- Styling: Tailwind CSS v3
- Charts: Recharts v3
- Export: XLSX (Excel export)
- Pages: Dashboard, Orders, Products, Articles, Users, Reviews, Warranties, RMA, Payments, Categories, Settings, Analytics, Hero Slides, Promo Codes

2. .env.local for tekalis-next contains API base URL as plaintext -- While NEXT_PUBLIC_* variables are meant to be client-exposed, the value is used both server-side and client-side, which could be confusing.
3. No authentication middleware -- There is NO middleware.ts file in the Next.js app. Dashboard pages (/dashboard/*) have robots: { index: false } in metadata but are NOT protected by any route guard. Any unauthenticated user can access /dashboard, /checkout, /wishlist, etc.
4. JWT token stored in localStorage -- Authentication tokens are stored in localStorage (accessible to XSS). The useAuth hook manually parses JWT to check expiry. This is less secure than httpOnly cookies.
HIGH
5. Massive code duplication between apps -- The shared package (packages/shared/) contains Redux store, slices, hooks, utilities, and contexts that are ALSO duplicated inside apps/tekalis-next/ with their own copies. The Next.js app does NOT import from packages/shared/. This creates maintenance burden and consistency risk.
6. Vite env variables used in Next.js -- The .env.local file contains VITE_API_URL and VITE_APP_NAME, which are Vite-specific and NOT used by Next.js. These are dead configuration. The Next.js app actually uses NEXT_PUBLIC_API_BASE.
7. constants.js.bak file present -- A backup of constants.js uses import.meta.env.VITE_API_URL (Vite syntax), which was replaced with process.env.NEXT_PUBLIC_API_URL (Next.js syntax). This .bak file is still tracked in the repo.
8. Inconsistent cart state shape -- The useCart hook reads state.cart.totalAmount but the cart slice defines state.cart.total. This would cause the hook to return undefined for totalAmount.
9. useAuth hook reads non-existent state.auth.token and state.auth.isAuthenticated -- The auth slice does not have token or isAuthenticated fields in Redux state. Token is only in localStorage. The hook works because isAuthenticated is computed as !!(user && token) where token comes from the hook's selector which returns undefined.
MEDIUM
10. No testing whatsoever -- Zero tests in the entire codebase. No unit tests, integration tests, or E2E tests.

- app/globals.css.bak, app/index.source.css.bak

12. dangerouslySetInnerHTML for JSON-LD -- Used in layout.jsx, page.jsx, and Footer.jsx. While necessary for inline scripts, the Footer uses <script> tags directly in JSX which won't work properly in Next.js (scripts in components should use next/script or be in <head>).
13. Hardcoded phone number in Footer -- Footer shows +221 77 123 45 67 which differs from the Schema.org data (+221786346946). These are inconsistent business data.
14. Footer Schema.org address inconsistency -- The Footer has "streetAddress": "Plateau, Rue X" while the layout has "streetAddress": "Fann, Rue 14". These are inconsistent.
15. Product detail uses MongoDB _id in URLs -- The product route is /products/[id] using MongoDB ObjectIDs. This is not SEO-friendly. The robots.js also blocks product pages from SEO crawlers via the sitemap.js using IDs instead of slugs.
16. No middleware.ts for auth or redirects -- Protected routes (dashboard, checkout, wishlist) have no server-side protection.
17. Shared styles are empty -- packages/shared/styles/index.css, tailwind.css, and custom.css are all 0-byte files.
18. dashboard/ directory at root of tekalis-next app -- Contains a single file orders/[id]/page.jsx, which duplicates the app/dashboard/orders/[id]/page.jsx. This appears to be a leftover.
LOW
19. PowerShell fix scripts in repo -- fix-tekalis-next.ps1 and fix-tekalis-next-corrected.ps1 are committed to the repository. These are development artifacts.
20. useDebouncedCallback uses useState for timer -- The useDebouncedCallback hook stores the timer ID in useState, which triggers re-renders. useRef would be more appropriate.
21. useErrorHandler references window.toast -- A global toast function that likely doesn't exist. The actual toast system uses a React context.
22. Large Navbar component -- 333 lines with inline JSX. Could be split into DesktopNav and MobileNav components.
23. Footer is 406 lines -- Contains inline schema.org JSON in <script> tags. Should use next/script with type="application/ld+json".
24. prop-types used alongside TypeScript setup -- The project has TypeScript configured but uses PropTypes for runtime validation in some components (Button, ErrorBoundary). These serve different purposes but it's a code smell in a TS-configured project.
25. Missing pages linked in footer/navigation -- /mentions-legales, /cgv, /cookies pages are linked in the Footer but have no corresponding route in the app/ directory.
26. .next/ directory tracked -- The apps/tekalis-next/.next/ directory appears in the glob results, suggesting it may be tracked in git despite being in .gitignore.
27. react-snap for pre-rendering -- The legacy client app uses react-snap (Puppeteer-based), which is unmaintained and has known issues.
13. Summary of Architecture Decisions
Aspect	Decision
Framework	Next.js 15.3.3 (App Router) -- primary
Legacy apps	Vite + React Router SPAs (client, admin)
Language	JavaScript (.jsx/.js), TypeScript configured but unused
State	Redux Toolkit + Redux Persist
Styling	Tailwind CSS v4, dark mode via class strategy
Icons	react-icons (FontAwesome), lucide-react (admin)
HTTP client	Axios (client-side), native fetch (server-side)
Deployment	Vercel for Next.js, Render for API backend
SEO	Comprehensive (dynamic sitemap, robots, OG, Schema.org, canonical)
Testing	NONE
i18n	French only (no internationalization framework)
Monorepo	npm workspaces (apps/, packages/)
